## 2. 本編に向けた問題点・技術的な課題

1. **地面が1本の平らな線しかない（最重要）**
   主人公・敵・弾・エフェクトが全部 `GROUND_Y`（画面上の固定の高さ）を地面として扱っています。足場・段差・穴・滑る氷・隠し部屋を作るには、「地形の当たり判定」を新しく作り、これらを置き換える必要があります。
   → プロローグは「平らな床だけの地形」として同じ仕組みに乗せれば、見た目と遊び心地を変えずに移行できます。

2. **武器の見た目が振りモーションに焼き込まれている**
   バット・椅子・机は、主人公の振りの絵の中に武器が描かれています。そのため、同じ「バット系」でも金属バットと木のバットを見た目で区別できません。
   → 当面は「バット系／椅子系／机系の3系統 × 性能・レアリティ・付与効果の違い」で装備のバリエーションを作り、見た目の差は色の光り方（レアリティ色のオーラ）や名前で出す案を推奨します。新しい系統（例：モップ、看板）を増やすには、その系統の振りモーション素材が1セット必要です。

3. **iOS Safari のセーブ消失リスク**
   iOS の Safari は、7日間そのサイトを開かないと `localStorage` を消すことがあります。ハクスラでは装備の消失は致命的です。
   → 「ホーム画面に追加」で遊ぶと消えにくくなる案内と、セーブデータの書き出し／読み込み（コピーできる文字列）を用意することを推奨します。

4. **コードが1つの大きな設定ファイル・グローバル変数に集まっている**
   データ量が増える前に、ファイルを用途ごとに分けておかないと、後からの修正が難しくなります（ルール7）。

5. **スマホでのメニュー操作**
   インベントリや装備比較は、リスト・スクロール・詳細表示が多く、今のキャンバス描画のメニューでは作りにくく、指でも押しにくいです。
   → 現世の画面やインベントリは、HTML の部品（DOM）をゲーム画面の上に重ねる方式を推奨します。戦闘画面は今のままキャンバスで描きます。

6. **処理の重さ**
   2倍解像度の描画に加えて、本編では敵や地形が増えます。古い端末向けに「画質：標準（1倍）／高（2倍）」の切り替えをオプションに入れることを推奨します。

7. **敵が1枚絵**
   敵はアニメーションのない静止画を、伸び縮みや点滅で動かしています。攻撃の予備動作を、光や記号のエフェクトで分かりやすく見せる必要があります。

## 4. 設計案

### 4-1. 全体の流れ
```
タイトル
 ├─ はじめから → プロローグ（STAGE 1〜5、今のまま） → 現世（拠点）へ
 └─ つづきから → 現世（拠点）
現世 ─出発→ 魔界ダンジョン 1階 → … → 出口で「次の階へ／帰還」
                      └ 倒れたら → 現世へ戻される（ペナルティは要相談）
```
プロローグの最後（STAGE 5「三つの世界」）からそのまま本編に入ると、シナリオの「STAGE 6 現世と魔界を巡る旅」とつながります。

### 4-2. 現世（拠点）
- 背景：夕方の街か自宅（手続き生成の背景を流用）。主人公と相棒が立っている。
- メニュー（DOM で重ねる）：**出発**／**装備**／**持ち物**／**ショップ**／**ステータス**／**セーブ**
- ショップ：回復（いちごミルクなど）、**水**（砂漠用）、**冷却材**（火山用・案）、帰還アイテム（案）。在庫は進行度で増える。
- 将来の拡張：NPC（友人ミオなど）、会話イベント、鍛冶（強化・分解）は、メニュー項目と「施設」データを追加すれば足せる構造にする。

### 4-3. ダンジョンと各階
- 1階層 ＝ 横に長い1本のマップ（横スクロールのまま）＋上下の足場。左端から入り、右端の出口（魔界のゲート）へ。
- 5階＝中ボス階（案）、10階＝ボス階。ボスを倒すと次のダンジョンが開放。
- **途中から再開（案）**：5階の中ボスを倒すと、次回から6階から始められる。

| ダンジョン | 環境ルール | 地形・ギミック | 敵の候補（手持ちの素材） |
|---|---|---|---|
| 草原 | なし（基本を学ぶ） | 段差・足場・浅い穴・草むらの隠しアイテム | スライム・キノコ・新芽・コウモリ・狼 → ボス：大型狼 or 森のゴーレム |
| 砂漠 | **水分ゲージ**：時間で減る（走り・攻撃で速く減る）。0 で熱中症 1段階目＝MP回復停止 → 2段階目＝攻撃・移動低下 → 3段階目＝HPが少しずつ減る。水で回復。まれにオアシス | 流砂（沈む・遅くなる）、砂嵐（視界）、サボテン（触るとダメージ。叩くと砂属性を得る） | クモ・骸骨・サソリ役（クモで代用）・人魂 → ボス：巨大クモ |
| 雪原 | **ジャンプ力 約75%**（2段ジャンプは残す） | 氷の床（滑る）、深雪（遅くなる）、つらら（落下）、凍った敵を叩くと砕ける | 狼・ゴースト・目玉・鎧騎士 → ボス：氷のドラゴン（ドラゴン素材の色替え） |
| 火山 | **各階に制限時間**（例：3分）。時間切れで即死ではなく「HPが大きく減り続ける」。冷却材・敵を倒すと少し延長 | 溶岩（ダメージ）、噴石、熱風（押し流す）。溶岩の近くで武器を振ると炎を得る | 小悪魔・人魂（炎）・ゴーレム・ドラゴン → ボス：炎のドラゴン |
| 魔王城 | 特殊な環境なし | 罠・狭い通路・エリート敵の部屋 | 騎士・死神・サキュバス・骸骨・巨大目玉 → ボス：魔王（巨大目玉 or 魔城） |

### 4-4. ランダム生成（理不尽を出さない仕組み）
完全なランダムではなく、**手作りの部屋パーツ（チャンク）をつなげる方式**を推奨します。
1. ダンジョンごとに、幅 960〜1920 程度の部屋パーツを 20〜30 個作っておく（平地の戦闘部屋、段差、足場渡り、穴越え、高台の宝箱、隠し部屋の入口、ギミック部屋など）。
2. 階層ごとに「長さ・敵の多さ・宝箱の数・ギミックの出やすさ」のルールに沿って、乱数で並べる。
3. 敵・宝箱・アイテムは、パーツ内の「置ける場所の候補」から乱数で選ぶ。
4. **必ずクリアできることの保証**：
   - 各パーツは、作る時点で「その環境のジャンプ力（雪原は低い）で通れる」ことを自動チェックする。
   - 並べた後にも、足場どうしの到達可能性を計算して、出口まで行けない並びは作り直す。
   - 開発用に、自動プレイで数百通りの階層を試すテストを用意する。
5. 乱数は「シード値」で再現できるようにする（不具合が出た階層をそのまま再現できる）。

### 4-5. 装備・ハクスラ
- **装備枠**：武器 3枠（今の Q で切り替える仕組みをそのまま使う）＋ 防具 1枠（制服・ジャージなど）＋ アクセサリー 2枠（案）
- **武器 ＝ 系統（バット／椅子／机）× 名前 × レアリティ × 付与効果**
  - 例：「錆びた鉄パイプ（バット系・コモン）」「パイプ椅子+3（椅子系・レア）攻撃+12% / 炎属性」
- **レアリティ**：コモン（白）→ アンコモン（緑）→ レア（青）→ エピック（紫）→ レジェンド（金）。上位ほど付与効果の数が増え、出る階層も深い。
- **付与効果の例**：攻撃力+、攻撃速度+、会心率+、属性付与（炎・砂・氷・雷）、HP吸収、ノックバック+、ガード時ダメージ軽減、必殺のMP消費軽減、移動速度（重さの軽減）
- **比較表示**：装備画面で、今の装備との差を「▲+12 / ▼-3」のように色付きで出す。
- **データ構造**：アイテムは「元データ（種類・基本性能）」＋「個体データ（レアリティ・付与効果・強化値）」に分ける。付与効果は効果名と数値の一覧にして、新しい効果を後から追加しやすくする。

### 4-6. 「周囲の物・敵の武器」で属性を得る仕組み（大事にしたい部分）
プロローグのコンロの仕組みを広げます。
- **環境オブジェクト**：たき火・溶岩（炎）、サボテン・砂だまり（砂）、氷柱（氷）、雷の結晶（雷）などに触れる、または武器で叩くと、**今の武器に一時的な属性が付く**（時間または回数で消える。HUD に表示）。
- **敵が落とす武器**：一部の敵（骸骨の剣、騎士の盾 など）が倒れると武器を落とす。その場で拾って使える「現地武器」（耐久つき）。持ち帰ると装備品として残る（案）。
- 属性の相性：炎→氷系・ゴーストに強い、砂→ひるみ、氷→足止め、雷→連鎖（案）。

### 4-7. 成長と難易度
- 主人公：レベル（HP・基礎攻撃）＋装備で強くなる。
- 敵の強さは「HPと攻撃力を増やす」だけにしない。
  - ダンジョンごとに敵の種類と攻撃パターンを変える
  - 深い階では、同じ敵でも行動が変わる（予備動作が短い、弾を撃つ、仲間を呼ぶ）
  - 敵の組み合わせ（遠距離＋近距離、盾持ち＋魔法）
  - エリート敵（名前つき・付与効果持ち・光る。倒すと良い装備を落としやすい）
  - 地形との組み合わせ（足場の上の弓兵、溶岩の近くの敵）
- ボス：それぞれ「攻略の鍵」を持たせる（例：雪原ボスは炎で弱点が出る、火山ボスは氷で冷やすと装甲が割れる）。

### 4-8. セーブ・ロード
- `localStorage` に、**バージョン番号つき**の1つの JSON で保存する（プロローグ進行、レベル、所持品、装備、ゴールド、到達階、設定）。
- 自動セーブ：現世に戻った時、階層を移った時。
- iOS 対策（2章の3）：セーブの書き出し／読み込みと、「ホーム画面に追加」の案内。

## 5. 推奨するファイル構成
今の「ビルドなし・`<script>` を順に読む」方式は崩さずに、用途ごとにファイルを分けます（`file://` でもそのまま動き、1ファイル版も作れる）。

```
src/
  （既存）config.js audio.js input.js backgrounds.js entities.js world.js game.js
  data/        … データだけ（後から数値を調整しやすい）
    items.js       武器・防具・消耗品・レアリティ・付与効果の定義
    loot.js        ドロップ表・宝箱の中身
    dungeons.js    5ダンジョンの定義（環境ルール・敵の出現表・BGM・背景）
    chunks/        ダンジョンごとの部屋パーツ（grassland.js など）
  systems/     … ルール
    rng.js         シードつき乱数
    terrain.js     地形の当たり判定（足場・壁・穴・特殊な床）
    stats.js       レベル＋装備 → 最終ステータス
    inventory.js   所持品・装備・ゴールド
    save.js        セーブ v2（移行つき）
    status.js      状態異常・環境（熱中症・凍え・時間制限）
  dungeon/
    generator.js   部屋パーツを並べて階層を作る＋到達可能性チェック
    dungeon_world.js  ダンジョン1階層の進行（World の戦闘部分を共有）
  hub/
    hub.js         現世のシーン
  ui/
    menu.js        DOM のメニュー部品（タップしやすいリスト・詳細・比較）
tools/
  tests/         … 自動プレイによる確認スクリプト（今は作業用フォルダにあるものを整理して入れる）
```

**既存コードへの影響**（ルール10）
- `entities.js`：主人公・敵・弾の「地面との当たり」を `terrain.js` の問い合わせに置き換える。プロローグは「平らな床だけの地形」になるので、挙動は変わらない想定。変更後に全ステージを自動プレイで確認する。
- `world.js`：戦闘の処理（当たり判定・撃破・エフェクト）を、ダンジョンと共有できる形に切り出す。プロローグの進行（会話・ウェーブ・ボス）はそのまま。
- `game.js`：タイトルに「つづきから」、シーンに「現世」「ダンジョン」を追加。
- `config.js`：プロローグのシナリオと敵・武器のデータは残し、本編のデータは `data/` に置く。
- セーブ：今の `{ unlocked, lv, exp }` を v2 に自動で移す（プロローグの進行は消えない）。
